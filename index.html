Digital Transformation Specialist
RESRG Automotive · Global automotive manufacturer
Jan 2025 — Present

A digital-transformation remit that became a data one. Plants ran on manual Excel trackers; I build the models and the products that replaced them — for the executives who need to read the business, and for the plants that run it.

For upper management. Inventory, production and cost for the whole group in one place — the summary leadership opens instead of commissioning a report, on models that reconcile across regions rather than per plant.
For the shop floor. Inventory and operations apps for the people actually running the line, built on those same models — so the number a plant sees and the number the board sees are the same number.

Energy forecasting for purchasing. Plant electricity consumption modelled from production variables, joining utility invoices with production and financial data so usage normalises against units sold rather than reading as raw kWh. In production.
Pipelines that keep up. Near-real-time models over 800M+ rows in Snowflake, refreshed by event-driven Prefect flows firing on the landing signal from an upstream CDC replication. A bit about me

What I enjoy most is the stretch between a messy process and a tool people actually use. I start with the people who run it — what they decide, what slows them down — simplify the process first, and only then build the pipeline and the app behind it. Something small in real use this week beats something complete in a slide deck.

I come from biomedical engineering and an MSc in data analysis and process improvement, and kept one rule from there: if someone is going to act on a number, they should be able to see where it came from. I build the same way outside work — both projects on this page are live, tested and run every day.

How I work

Business first

A model is worth what the decision behind it is worth, so I start from who acts on the number and how we will know it worked.

Simplify, then automate

Automating a broken process only makes it fail faster. I strip it back with the people who run it first, and build for what is left.

Long-term solutions

Systems, not one-off tasks: clear definitions, tested models and lineage the next person can follow without me.

Ship early, learn fast

Agile in practice: a working version in users' hands within days shows what is really needed before the rest gets built.
